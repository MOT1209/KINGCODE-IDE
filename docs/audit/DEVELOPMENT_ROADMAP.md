**نتائج التحقق الحي (2026-11-02 — نجحنا بإعادة الإنتاج قبل أي تعديل):**
- **1.1 → مُثبت**: نقرة واحدة على `#btnThemeToggle` تُطلق المعالج مرتين (`invocations: 2`)؛ المظهر يبقى كما هو (تبديل مزدوج = لا شيء). نفس التوصيل في 9 أزرار.
- **1.2 → تاريخي مُصلَح**: recursion غير قابل للإعادة في HEAD؛ `UI.toggleSidebar()` شغّال نظيف — يتبقى التحقق بعد تغيير أسلاك الأزرار فقط.
- **1.3 → مُثبت ×2**: `GET /%` → `URIError: URI malformed @ tools/server.js:42:17` ثم `Exited with code 1` — السيرفر يموت بالكامل.
- **1.4 → سلوك مؤكد**: `/..%2f..%2fREADME.md` → **200** (طُبّع المسار وأُسقطت `..` وفُسّر داخل الجذر)؛ ملف مفقود → **404 وليس 403**. لا تسريب خارج الجذر ظاهراً، لكن الحماية عرضية وليست مقصودة — يلزم `resolve()` + فاصل دليل.
- **1.7 → مُثبت**: أول تكرار يصنع `index copy.html`؛ الثاني يعيد `false` بصمت (`secondOk: false`).
- **جديد 1.10/1.11**: مؤكدان حياً (ترويسة ACAO `*` على كل استجابة؛ `Content-Type: application/manifest+json` على `.json`).

## قواعد التنفيذ (مُلزِمة)

1. كل إصلاح → كوميت مستقل برسالة توضح السبب والمرجع.
2. كل ادعاء "نجح الاختبار" → يتضمن أمر التنفيذ وخرجه الفعلي.
3. لا حذف functionality قبل تبرير مكتوب.
4. لا اعتماد مكتبة جديدة قبل بحث كافٍ وحجة مكتوبة.
5. الوصول لمرحلة جديدة فقط بعد خضراء معيار القبول للمرحلة الحالية.
6. عند انسداد (بيانات اعتماد/بنية خارجية) → توثيق الانسداد ومتابعة مهام مستقلة.
